# 阶段四：可靠性与恢复

2026-09-14。本阶段继续使用虚构材料，完善原有操作的可靠性。岗位分析、补充事实、草稿确认的顺序保持一致。

## 可以在页面看到什么

打开岗位下的任务记录，顶部会显示模型请求次数、工具次数、耗时、Token 用量及该任务的重试上限。某次请求没有返回用量时，总用量显示未知，同时列出已知累计 Token 和用量未知的请求数。

新建任务会保存当时的预算与重试配置。修改本机配置或重启服务，不会重置已有任务的次数。阶段三创建的任务没有重试配置，继续按零次自动重试处理。

状态轮询只更新次数及读取任务状态。进入等待补充、等待确认或出错状态后停止轮询，保留编辑内容。存储错误页面留在当前步骤，避免反复自动刷新。

## 错误时如何处理

| 情况 | 应用行为 | 你可以做什么 |
| --- | --- | --- |
| HTTP 429、500、503 | 按任务配置有限重试，每次计入总调用上限 | 等待结果，停止后查看尝试记录 |
| 超时、连接失败 | 停止，不自动重发 | 检查网络和已有记录，需要时从岗位新建任务 |
| 鉴权、余额、参数错误 | 停止并显示对应类别，不显示服务商原始错误正文 | 在本机检查相应配置或账户 |
| 输出截断、非法 JSON、未知工具 | 停止，保留已完成进度与已知用量 | 核对记录，需要时重新分析 |
| 请求已登记但结果未保存 | 停止，标记上次结果不确定 | 不把它当作零费用；保留记录后决定是否新建任务 |
| 本地存储临时不可用 | 保留未消费的操作和检查点 | 修复存储后点击“继续未完成任务” |
| 已引用事实或 JD 在运行期间变化 | 停止使用旧依据 | 按最新资料重新分析 |
| 检查点丢失，但已有业务进度 | 停止从头重跑 | 恢复完整备份，或基于现有资料新建任务 |

单个模型适配器调用仍只发一次 HTTP 请求。业务任务编排决定是否重试；默认最多额外一次，配置支持 0–3 次，退避等待依次为 0.25、0.5、1 秒。请求次数达到总预算时不会继续等待和重试。基础连通性探测、字段提取和固定阶段三真实测试脚本不自动重试。

## 为什么中断后不会重复保存

流程分成三层：

1. **调用账本**：请求前登记，每次尝试有稳定标识。响应已保存时直接复用；结果不明时停止。
2. **执行检查点**：同步保存图节点进度，记录当前等待哪个问题；旧答复不会被提交给下一道问题。
3. **业务事务**：事实确认、材料保存使用稳定操作标识及唯一约束。业务已经提交，即使随后进程突然退出，恢复也返回原结果。

草稿编辑与“确认保存”指令现在共用一个事务。确认指令保存失败时，本次编辑一同回滚，可以用原页面重新提交。同一任务由操作系统文件锁串行执行；进程退出后锁自动释放，重复点击不会并发运行同一任务。

## 本地恢复体验

仍可使用虚构区的新任务演示：

1. 在任务等待补充或等待草稿确认时，记下任务链接。
2. 正常停止自己启动的服务，再用启动命令重启。
3. 打开原任务链接，检查等待步骤与调用次数仍在，然后继续操作。

无需手动损坏数据库或制造断网。进程突然退出、错误响应、并发点击等破坏性故障已经在隔离的临时目录中自动测试。

备份时正常停止服务，保留整个 data 目录，包含业务数据库、工作流检查点和 originals。不要只恢复一个数据库；本阶段升级前已保留一份本机完整备份。

## 资料与测试边界

模型发送边界会隐藏可识别的邮箱和中国大陆手机号，本地原件与事实文本仍保留原样。这是有限格式的预处理，不能代替真实资料的人工核对，也不覆盖所有个人信息格式。

工具仍只有当前资料区的已确认事实检索。模型不能选择任意文件、其他资料区、SQL、命令行或外部网址。测试覆盖 JD 注入诱导越权、目录链接越界、假 Key 回显、页面转义和请求来源校验。

本阶段故障测试不调用真实 API，不消耗真实 API 额度；测试通过证明这些工程分支可复现，不证明未来所有输入都无语义错误。真实简历/JD 的效果验收留在阶段五。
