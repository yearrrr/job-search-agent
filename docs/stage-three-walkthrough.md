# 阶段三：从岗位分析到材料确认

阶段三已接入实际 LangGraph 业务图。继续使用虚构资料即可，不需要提供真实简历。

## 在网页上体验

1. 在看板打开一个岗位，找到“分析岗位，准备材料”。
2. 选择“离线流程演示”或“DeepSeek 实际运行”，点击“开始分析岗位”。后者会把该岗位要求和检索出的已确认事实发送到 DeepSeek；前者不联网。默认选离线。
3. 查看逐条分析：“有证据支持”“明确不符”“资料不足”。每条有 JD 位置，有证据的结论还能返回资料来源。加分项未知不代表不符合门槛。
4. 遇到追问，可以提交一段补充、稍后回答、暂不回答当前项，或“暂不补充，生成草稿”。暂不回答会保持未知，本任务不重复追问这项。
5. 补充先成为原始 TXT 和待确认候选。页面展示内容后，点击“确认以上补充为事实并继续”，它才进入已确认档案。也可以不采用。所有问题处理后最多重新分析一轮。
6. 草稿有简历段落、项目介绍、自我介绍，以及修改依据和待核实项。模型选择、排序已有事实；程序引用事实原句。首版限制自动改写，避免新增经历和数字。
7. 可先“保存编辑，稍后确认”，也可直接“确认当前内容并保存版本”。确认按钮会保存文本框当前内容，再创建材料版本。个人编辑保留记录，不自动变成事实证据。
8. 材料页提供 Markdown/TXT 导出，岗位页保留每次任务和材料版本。下一次分析另建任务，旧版本保留。投递状态仍由你手动记录。

当前档案仅有部分事实已确认，因此看到多项“资料不足”是预期行为。想改善分析，先在“原始资料”确认相关经历，再新建分析任务。

## 模型、工具和程序各做什么

~~~mermaid
flowchart TD
    A[岗位要求与已确认事实快照] --> B[模型提出检索调用]
    B --> C[程序检查工具名、参数和预算]
    C --> D[SQLite 查询当前已确认事实]
    D --> B
    B --> E[校验三类分析与引用]
    E --> F{有未处理缺口}
    F -->|有| G[中断等待回答或跳过]
    G -->|回答| H[新增事实另行确认]
    G -->|跳过| F
    H --> F
    F -->|无| I[模型选取事实并给编辑建议]
    I --> J[程序组装带来源的草稿]
    J --> K[中断等待编辑确认]
    K --> L[事务保存材料版本与导出]
~~~

普通函数调用由程序代码直接决定参数。这里的工具调用是模型返回工具名和 JSON 参数，程序校验后执行本地函数，再把结果作为 tool 消息交还模型。网页“运行记录”可以看到这三步，离线替身也走同一套图和真实数据库检索。

工具只有 search_confirmed_facts。参数仅为 query、category、limit，资料区和事实版本由任务绑定。中英关键词检索可配合分类查询；学习笔记、待确认/已排除事实、其他资料区、材料草稿均不能当作经历证据。每次最多返回 8 条、约 8000 字符，遗漏数量会明确返回。

模型输出先做结构与引用校验：要求不能漏项，事实 ID 必须来自本轮实际检索，unknown 必须提出问题。草稿模型只能选择事实 ID，不能自行提供新的经历正文；编辑建议中的无据数字会被拒绝。引用存在仍不能自动证明分析语义正确，复杂要求与建议仍需人工核对。离线规则用于理解流程，不能代表真实模型的语义效果。

## 为什么重启后能继续

- app.sqlite3 保存任务摘要、用户指令、每次尝试、草稿修订和材料版本。
- workflow.sqlite3 保存正式业务图检查点；阶段一的冒烟演示仍用 checkpoints.sqlite3，互不混用。
- 等待补充或确认时，图通过 interrupt 释放运行资源。下一次 POST 把用户指令连同中断 ID 存下，再用 Command 恢复。
- 每个任务用操作系统文件锁串行执行。重复按钮操作和事实/材料确认使用数据库事务及唯一键；旧页面不能覆盖新草稿。
- 每次调用先登记预算，再执行；已保存响应可重用。若请求已发出但结果未落盘，任务停止并说明不确定性，不自动补发一次付费请求。

关掉自己启动的服务，再按运行说明重启，打开原任务链接即可继续。处于“处理中”的未完成任务需要点击“继续未完成任务”；刷新页面本身只读取状态。任务失败时保留进度和尝试记录，根据提示检查后可以新建任务。

本阶段无自动重试，MAX_RETRIES 仍为后续可靠性工作预留。页上 Token 未知表示服务未返回用量或使用离线替身，不能解释为零。费用尚未按实时价格折算。

## 代码阅读顺序

| 文件 | 作用 |
| --- | --- |
| src/job_search_agent/task_web.py | 同源/CSRF 校验后的页面动作，创建任务与提交答复 |
| services/tasks.py | 业务快照、操作去重、串行锁、调用预算与账本 |
| agent/workflow.py | 正式 LangGraph 节点、工具循环、中断与恢复 |
| agent/retrieval.py | 查询已确认事实、分类与关键词检索、范围与结果限制 |
| agent/contracts.py | 分析/草稿的严格结构及引用验证 |
| agent/business_model.py | 不联网的流程测试替身 |
| services/drafts.py | 草稿组装、编辑记录、事务确认和材料版本 |
| tests/test_stage_three*.py | 实际图、子进程恢复、故障注入与网页测试 |

阶段一 agent/graph.py 和 agent/tools.py 保留为最小学习演示，正式岗位功能使用 workflow.py 和 retrieval.py。

下一阶段是可靠性补强：扩大异常、并发、预算和故障恢复覆盖。真实个人资料效果验收仍在之后进行。
