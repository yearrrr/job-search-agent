# 第二版第三批 定制简历交付记录

日期：2026-09-15。版本：0.2.0b3，数据库 schema 7。

## 使用方法

1. 打开已保存岗位，点击“选择经历并生成简历”。准备分析完成页也有下一步入口。
2. 可先推荐项目，查看理由，再使用推荐进入选择页；也可直接手动勾选。
3. 选择 1–40 条已确认经历，增减项目、调整同类顺序、填写写作偏好，选择 DeepSeek 实际撰写或离线演示。
4. 等待结果自动出现，逐段核对来源并修改正文，点击“保存当前草稿”。
5. 勾选内容真实准确，确认此版本，打开下载页取得 Word 和 PDF。继续编辑后再次保存、确认会生成新版本。

推荐只处理项目，完整简历还可包含基础信息、学历、技能、实习、奖项和专利论文。没有已确认资料的类别不会填充虚构内容，可在经历库独立补充其他项目。

## 实现与保护

- 推荐与写作复用 V2 任务账本，按输入快照去重，记录实际用量，提供处理中自动更新与中断继续入口。
- 推荐限定项目编号与岗位要求编号；写作固定人工选择的经历及顺序，逐段绑定来源。结构或数字不合法最多反馈两次后停止。
- 写作只发送所选非基础经历及 JD，基础信息本机回填，其他内容中的邮箱和手机号进行隐藏。
- 新增数字检查不等于完整语义验证；学校、时间、职责、技术和成果仍需要人工核对。
- 草稿采用版本号防止并发覆盖；确认后保存不可变版本。重复确认同一草稿不会创建多个版本。
- 保存、确认采用局部请求；未保存修改关闭确认按钮，失败保留输入。项目排序、确认成功后的下一步链接直接生效。
- Word 使用 python-docx，PDF 使用 ReportLab 和嵌入的宋体。默认 Letter 纵向、11pt 正文，超长内容自动分页，两种格式共享内容与来源快照。
- 增加 resume_drafts、resume_draft_history、resume_versions 三表；保留首版材料和此前任务。

最终普通 wheel 安装环境全量 **248 项测试通过**（99.39 秒）；Ruff 检查及格式检查通过。保留一条来自 Starlette/AnyIO 的上游弃用提示，无失败或跳过。

新增 20 项后端测试覆盖推荐/选择、资料区隔离、只发送所选经历、联系方式本机回填、错误编号与新增数字、限定重写次数、预算、过期资料、草稿冲突、并发幂等、历史版本、中文导出、CSRF 和完整页面路由。

DOM 行为测试使用真实 Jinja 页面和 jsdom，验证重复点击只提交一次、局部保存、版本同步、确认后的下一步入口、修改后重新确认、失败保留输入以及项目排序。本次内嵌浏览器连接失败（nodeRepl.fetch request failed），没有把 DOM 测试当作浏览器人工点击验收。

两份样例的 Word 和 PDF 均完成逐页渲染检查，最终各一页，无标题装饰线、字体缺失或内容截断。Windows 捆绑环境没有 LibreOffice；先运行标准 render_docx.py 确认缺少转换器，再由独立 Word 实例完成 DOCX 转 PDF，复用标准渲染器生成 PNG 检查。生产 PDF 由 ReportLab 生成，不依赖本机 Word。

数据库使用开发前在线备份比对，原有 30 张表内容、28 个非数据库文件及 .env 保留；完整性检查和外键检查通过。备份覆盖主库、原件和数据目录中的旧备份/测试库，主库比对以实际在线备份为准。
