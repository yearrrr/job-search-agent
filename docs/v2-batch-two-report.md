# 第二版第二批：岗位准备交付记录

日期：2026-09-14。版本：0.2.0b2。数据库 schema：6。

## 已交付

- JD 入口支持 1–6 张 PNG/JPEG/WEBP 截图、直接粘贴文字，以及截图配补充文字。每张最多 5 MB，总共最多 15 MB；截图先在独立子进程校验和转换，再由 LLM 识别语义。
- LLM 返回公司、岗位、岗位编号、招聘批次、来源链接、JD 原文、职责、硬性条件、加分项、地点、薪资和截止日期。缺失信息留空；先核对再保存。另有不调用模型的手动填写入口。
- 原始截图和输入独立于个人履历库保存，模型识别稿、核对稿与岗位关联可回查。JD 不进入已确认个人经历。
- 岗位核对保存后原地显示“下一步”；岗位字段和状态原地更新，保留其他未保存输入。
- 切换到准备中后展示“现在分析”或“暂时只更新状态”。状态操作与 GET 刷新不会创建模型任务；可以稍后从岗位页启动分析。
- 主 Agent 新增 LangGraph 准备分支和三个工具：search_experiences 查摘要，get_experience_details 读完整经历，get_evidence 查证据。模型选择查询，程序校验参数、已发现 ID、资料区、确认状态与快照版本。
- 每条岗位要求展示已有支持、明确硬性条件冲突或待确认；给出引用、具体补充问题、学习优先级、步骤及练习完成标准。加分项/职责缺资料不能判为硬性冲突，部分满足仍需确认。学习建议独立于个人经历，不会自动变成用户能力。
- 同一档案/JD 版本、同一运行模式复用已有活动或已完成任务；同任务相同工具参数复用结果并压缩重复消息，连续第四次重复查询停止。缓存命中仍记一次工具请求并计入预算。
- 持久化每次模型/工具尝试与用量。确定且已保存的模型响应可重放，存储恢复不重置预算；结果不确定时停止重发。限流/服务不可用仅有限重试，超时和鉴权失败不自动重试。
- 首版任务、草稿和检查点保留，岗位页收在“首版流程与历史材料”中。

第二版准备分支用业务尝试账本重放恢复 LangGraph 循环；它不复用首版的 SqliteSaver 检查点。资料与 JD 解析是由操作触发的有界后台任务，不是独立自主 Agent。

## 数据与恢复

升级前创建当前数据的 SQLite 在线备份、原件副本、源码包和本机配置副本，位于 .local/backups/v2-batch2-before-20260914-184127。备份包含本批开始时 26 张表、5 份文档、48 条事实、4 个岗位和 6 个首版任务。

schema 6 仅增加 v2_runs、v2_run_attempts、jd_imports、jd_confirmations 四张表及索引。恢复时使用备份中成套的数据目录与对应源码，避免把旧程序与新 schema 混用。当前 .env 不作修改，已有原件和任务不被重新解析或自动执行。

任务因程序中断停留在处理中时，可以点击“继续未完成任务”。若某次请求已发送但结果未落盘，任务停止并说明原因；不会假装该次调用免费或自动重发。任务引用的岗位/档案版本变化时，应返回岗位页基于新资料重新分析。

## 当前范围与下一批

本批每份 JD 的职责、硬性条件、加分项合计支持 1–24 条分析要求；过长的一条请在核对页分行。关键词检索按类别和词项匹配，尚未采用向量检索。模型引用和结构校验不等于语义正确，最终仍需用户核对。

补充问题在分析结果中展示；当前可独立补充并确认个人经历，再从岗位页更新分析。第二版此分支暂不在原任务里进行多轮追问。

下一批实现按岗位推荐/选择项目、LLM 撰写完整简历、编辑确认和 Word/PDF 导出。模拟面试 Agent 仍为后续扩展。
