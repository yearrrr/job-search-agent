# 岗位准备：无效经历编号纠错修复

日期：2026-09-15。版本：0.2.0b2.post1。数据库 schema 仍为 6。

## 触发问题

主 Agent 已搜索到经历后，调用 get_experience_details 时传入了未返回过的编号。原执行器正确拒绝了整批读取，但将 tool_rejected 直接升级为任务终止，没有给模型纠正参数的机会。

因此此次修复保留了校验和原始编号，不按相似度替换编号、不放开其他资料区、不把错误请求中的有效子集悄悄当成全部成功。

## 处理方式

- 无效工具名称、参数格式或经历编号均计入工具尝试账本和原预算。
- 可纠正的 tool_rejected 转为工具反馈，说明无效编号、当前允许使用的工具，以及本任务已经发现的可用经历 ID、名称与分类。
- 获取证据前仍需读取完整经历；错误提示不会泄露未确认经历、其他资料区或未检索到的条目。
- 纠正提示最多反馈 3 次，第四次无效请求落账后停止，使用明确的 tool_correction_limit 错误。更小的模型/工具总预算仍优先限制调用。
- 失败请求保持 failed，不进入成功缓存，不增加“已读取详情”或“已取证”集合。
- 原因是 tool_rejected 的旧准备任务出现“纠正参数并继续本次分析”按钮。POST 和 CSRF 校验后恢复原任务，沿用原快照、限额与尝试记录；GET 不会触发恢复。
- 资料版本变化、存储不确定尝试、鉴权/网络等其他错误保留其原处理方式，不冒充可纠正的编号错误。
- 任务页面显示已拦截的无效请求次数；点击恢复后自动更新进度和结果，不必重复刷新。

LangGraph 循环从调用账本重放，错误次数也在重放中重建。此次保留原系统提示词与工具 schema，保证旧任务前序请求与缓存指纹一致。
