## 修复与人工核对

第一轮发现资料 INSERT 的占位符数量不匹配，修复后导入测试通过。随后检查虚构 PDF 发现续行被拆为候选，修正为合并句子并保留 `fact_sources` 中的所有行；测试明确检查“没有生产环境部署经历记录”没有被断开。开发过程中已生成的虚构区待确认候选同步修正，旧文字保留在修订历史，孤立页码/续行标为已排除；没有修改用户个人事实。

虚构 PDF 已用 Poppler 渲染并逐页检查：一页、中文完整、无重叠或截断，原始与分发副本内容一致。页面已进行桌面/窄屏查看，资料列表、原文核对和看板可访问；其他完整表单流程有自动化测试覆盖。浏览器实际执行：确认一条虚构学历后档案显示 1 条；将 DEMO-AI-001 从已收藏改为准备中后历史为 2 条；保存备注；创建待办并标记完成；切换真实区仍为 0 份资料、0 条事实、0 个岗位。

最后的真实浏览器表单检查发现 `no-referrer` 页面策略使导航 POST 的 Origin 变成空来源，从而被正确的同源检查拒绝。改为 `same-origin` 来源策略，保留本地表单所需的来源，同时跨源跳转不带页面来源；没有放宽 Origin、CSRF 或跨站校验。浏览器操作复测成功，7 项相关 Web 回归在最终修复后通过（3.32 秒）。

普通安装核验：在阶段一建立的第二个独立虚拟环境 `.local/repro-venv` 安装更新的锁定依赖与普通 wheel，`pip check` 无冲突。确认实际导入的是该环境安装包，PDF 样例、模板、schema 均可用；从应用关闭/重新创建后仍能查到已确认事实，重复加载仍为 3 个岗位。此前完整 87 项测试通过后，最终来源策略修复额外回归 Web 用例。
