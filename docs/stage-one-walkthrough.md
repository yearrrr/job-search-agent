# 阶段一：代码怎样连起来

本阶段解决“能否在本机稳定运行、隔离测试和保存流程进度”，尚不解决真实简历提取或岗位匹配。工程演示使用确定性模拟模型，所以可以测试系统行为，不需要付费，也不会把合成结果当成你的经历。

## 1. 先从 Web 入口看普通程序

`cli.py:main()` 读取配置，并把 FastAPI 应用交给 Uvicorn，只绑定本机。`config.py:load_settings()` 只读取允许的配置名；环境变量覆盖 `.env`，Key 用 `SecretStr` 封装、从序列化结果排除。验证失败只输出固定中文提示，不输出可能包含秘密的原始参数。

`main.py:create_app()` 在生命周期启动时调用 `Database.initialize()`，建立本地 SQLite 表；首页通过 Jinja2 模板渲染，健康检查执行实际数据库查询。前端接收的上下文是显式白名单，目前只有运行模式。

这一路没有模型：网页、配置和数据库读写是确定的程序行为。把这些交给 LLM 决定只会增加错误和费用。

## 2. 再看一个真正运行的 LangGraph

```mermaid
flowchart LR
    A[模拟模型提出检索调用] --> B[白名单与参数校验]
    B --> C[返回虚构资料及来源]
    C --> D[模拟模型组织演示文本]
    D --> E[保存图状态并等待确认]
    E -->|同一任务 ID 恢复| F[数据库幂等保存]
```

入口是 `agent/graph.py:run_smoke()`：任务 ID 会作为 LangGraph `thread_id`。`build_graph()` 创建实际 `StateGraph`，节点并非仅是一次模型调用的别名。

1. `model` 节点调用模型接口。`DemoModel` 首次返回结构化 `ToolCall`，选择 `search_demo_evidence`。
2. `tools` 节点先检查工具名称和参数，调用 `agent/tools.py:execute_demo_tool()`；它只检索内置的虚构文本，返回 `fictional-profile:1` 来源 ID。
3. 工具结果以 `role=tool` 返回下一次模拟模型调用。第二次返回带来源的演示文本。
4. `prepare_confirmation` 保存可理解的等待状态，`confirm` 调用 `interrupt()` 后暂停。
5. `resume` 使用相同任务 ID 和 `Command(resume=True)` 继续，`save` 调用业务函数保存结果。

这里模型模拟的是“选择工具、组织表达”；程序实际执行参数校验、检索、计数、中断、持久化与保存。真实 DeepSeek 接口已有单次请求与工具响应解析，但尚未接入正式求职任务，也没有实测真实模型的工具选择质量。

## 3. 两个数据库分别记什么

`data/checkpoints.sqlite3` 保存图状态，回答“进行到哪个节点、还有哪些输入、等待什么确认”。`data/app.sqlite3` 保存演示确认结果和探测指标，回答“确认结果是否已经保存、某次 API 尝试结果是什么”。

图恢复可能重跑某个节点，不能只靠前端禁用按钮防重复。`db.py:save_smoke_once()` 使用任务 ID 唯一约束和 `ON CONFLICT DO NOTHING`，同一确认被重放时返回原结果。已经提交的演示结果不因重复恢复而覆盖。

确认节点之前没有数据库结果写入或模型生成；恢复确认时不再走前面的模型节点，所以示例中仍是 2 次模型请求。正式材料的操作 ID、版本冲突、并发与跨库故障处理还要在业务阶段实现和验证。

## 4. 为什么模型接口不自己重试

`agent/model.py` 定义统一 `complete()` 接口。`DemoModel` 无网络；`DeepSeekModel` 只发一个 HTTP 请求，检查离线模式、密钥、输入与输出限额，并将外部异常翻译为固定错误类别。

重试不是免费的：它也是新请求。后续编排层应在预算登记后决定是否再次调用适配器。当前探测只允许一个尝试，避免适配器与编排层各自重试导致次数相乘。

`probe.py:check_api()` 使用固定非敏感文本，先在业务库登记尝试，再请求模型，最后保存耗时和接口返回的 Token。进程在请求后崩溃时留下 `started` 和未知用量，不伪造成功或零用量。工具返回的字符串、参数、HTTP 原始报错不能进入秘密日志。

## 5. 怎样验证，以及还不能证明什么

- 配置与模型测试验证：默认不联网、Key 不进入可见配置/错误/探测记录、超时与各类 HTTP 错误只尝试一次、非法结构被拒绝、未知用量不计零。
- 图测试使用真实 SQLite 检查点和实际检索函数；还启动彼此独立的进程，先等待确认、退出，再查询/恢复，并检查重复保存只有一条。
- Web 测试检查首页、静态资源、健康检查、Host 限制和安全响应头；不向真实服务商发送请求。
- Git 规则测试防止常见私有目录、数据库、Key 配置和缓存被默认纳入版本控制。

格式合法和来源 ID 存在，仍不能证明自然语言判断正确。现阶段的模拟模型输出是固定虚构文本，不是 A05/A06 的效果证据。真实资料、中文检索、追问闭环、草稿版本、完整中断故障恢复及真实成本评测均按后续阶段推进。

依赖树中包含 LangSmith 和 `sqlite-vec`；图执行显式关闭第三方追踪，代码没有启用向量索引、embedding 服务或云日志。它们的安装不表示首版新增了这些业务组件或服务。
