# 首版需求与验收标准

整理日期：2026-09-13。依据：[用户原始需求](requirements-original.txt)。本文件整理范围与验收条件，不代表功能已实现。实施细节中的默认值单独记录于[待确认事项](decisions-and-questions.md)，不得当作用户已确认的业务事实。

## 1. 项目目标与开发约定

开发一个自己实际使用的个人求职管家 Agent，并通过开发理解完整工程流程，为 Agent 开发岗位秋招积累可讲解的项目经历。用户接触过 LLM 微调和强化学习，但缺少完整应用落地经验；关键设计和代码串联必须用中文解释。

确定的技术路线：Python；LangGraph 负责任务编排、状态管理、人工确认和中断恢复；DeepSeek API 负责理解、生成和工具调用；SQLite 保存档案、岗位、任务、草稿与求职记录；本地目录保存原始文件和生成材料；界面优先 FastAPI＋服务端模板＋少量 JavaScript。

开发约定：

1. 每阶段先解释目标和设计，再实现，再测试；测试不推迟到最后。
2. 保留已有文件与用户修改，不擅自覆盖。
3. 不引入首版无关的复杂组件。
4. 新增付费服务、扩大资料上传范围或改变核心需求前，先询问用户。
5. 区分已实现、已测试和计划中；不将模拟测试等同真实验收。

## 2. 业务范围

首版服务一个本地用户，完成：**确认个人资料 → 导入岗位 JD → 分析要求与经历 → 缺失信息追问 → 生成材料草稿 → 用户确认保存 → 记录求职进展。**

首版不做：全网职位爬取、招聘网站登录、自动网申、自动投递、自动发邮件或联系招聘人员；接管邮箱、微信或日历；语音或视频面试、完整学习平台；复杂排版的完整 Word/PDF 简历；微调与本地模型部署；强制向量数据库或多智能体；无人值守定时任务。这些属于可能的后续扩展。

## 3. 功能需求

### F1：个人资料导入与确认

- 支持文字型 PDF 简历、UTF-8 文本和 Markdown 补充材料；保留原文件且不修改。
- 提取教育、项目、技能等信息，先进入待确认状态，可由用户修改、确认。
- 不确定的信息留空或标为待确认，不猜测日期、经历、数字等。
- 重要事实保留来源定位：文件、页码或文本片段。
- 扫描型 PDF、解析失败或不支持的文件须明确报错，并提供粘贴文本替代入口。
- 求职目标、城市等偏好由用户明确设置，不根据聊天语气推断。
- **只有已确认档案可以作为后续材料中的个人事实依据。**

### F2：岗位导入与管理

- 用户粘贴 JD 正文，填写公司和岗位名称，来源链接可选；链接可以只记录，不承诺自动读取。
- 保存原始 JD、来源和导入时间；提取职责、硬性条件、加分项、地点等。
- 未写明的截止日期、薪资等保持未知；用户能核对、修正提取字段。
- 重复导入给出提示，不覆盖已有材料或求职记录。
- 判重考虑公司、岗位 ID、招聘批次或正文等信息，不能只比较岗位名称。

### F3：岗位分析

- 结合岗位、已确认个人档案及相关资料，逐项区分：有经历证据支持、有明确依据表明条件不符、资料不足需要确认。
- 每个重要结论关联 JD 要求及对应经历证据，或具体缺失的信息。
- “简历没写”不能推导为“用户不会”；模型建议不成为已确认事实。
- 不输出无依据的录用概率或通过率。
- 关键资料不足时提出具体问题；用户可以回答、稍后回答或暂不回答，保留未知状态。

### F4：岗位材料草稿

- 生成针对岗位的简历段落建议、项目或自我介绍表达建议，以及修改依据和待核实内容。
- 只调整真实内容的表达、顺序和重点，不新增未经确认的经历、技术使用、职责或效果数字。
- 重要个人经历陈述可追溯来源；不能以生成内容自身证明真实性。
- AI 草稿不得自动写回事实档案；新增事实必须先让用户确认。
- 草稿可编辑、留存版本、导出 Markdown 或文本；保存新版本不覆盖原始简历。
- 首版不要求完整投递版 PDF。

### F5：求职进展管理

- 岗位看板状态：已收藏、准备中、已投递、面试中、已结束。
- 每个岗位关联材料版本、备注与待办。
- 状态变更由用户明确操作或确认，并保留时间和历史。
- 生成或保存草稿不能自动代表已投递；不能根据语气推测面试结果。

### F6：任务状态与恢复

- 界面显示处理中、等待补充、等待确认、已完成、失败等可理解状态。
- 显示当前步骤和错误原因，不能长时间只有“加载中”。
- 等待用户时保存状态，不持续调用模型；服务关闭重启后能恢复待处理任务。
- 重试或重复点击不得重复保存、建档或更新业务状态。

## 4. Agent、RAG 与数据原则

| 分工 | 职责 |
| --- | --- |
| 模型 | 理解任务与 JD；判断信息缺口；选择允许的检索工具；组织分析与草稿 |
| 程序 | 权限、参数校验、数据读写、状态转换、版本管理、防重复操作、预算限制 |

必须实际使用 LangGraph 管理流程，并完成模型提出工具调用、程序校验执行、结果返回模型的循环。单次文本生成调用不能冒充 Agent。

先实现单主 Agent。独立审核 Agent 仅作为后续实验；新增前先建立单 Agent 基线，再比较错误率、成本和耗时。

| 数据类别 | 内容 | 使用原则 |
| --- | --- | --- |
| 个人事实 | 已确认的经历、技能、偏好 | 结构化保存来源与确认状态 |
| 原始资料 | 简历、项目说明、笔记、JD | 保留原文、按需检索；学习资料与经历证据区分 |
| 业务状态 | 岗位、任务、草稿版本、求职进展 | 精确数据库查询，不依赖聊天记忆 |

读过技术文档不代表做过相关项目。最小 RAG 使用结构化查询、关键词或全文检索；结果保留来源，按任务选择必要片段，不无差别传入全部资料。无证据时说明不足。草稿不得进入证明个人经历的证据集合。首版不要求 embedding API 或向量库；后续引入需说明收益、成本和新增的数据传输。

## 5. 隐私、安全与成本

### 本地与外部数据边界

- 原始资料、SQLite 数据库、生成材料保存在本地。
- 明确告知使用 DeepSeek 时，请求中的文本仍发送至服务商。
- PDF 本地解析，不默认整份上传；只发送当前任务必要文本，岗位匹配尽量移除手机号、邮箱和详细地址。
- 不默认向第三方日志平台上传完整提示词或个人资料。
- Key 来自本地环境变量或 Git 忽略的配置；不要求发到聊天中，不进入前端、日志、报错或测试报告。
- 提交前排除真实简历、个人数据库、生成材料和敏感日志；公开示例明确标记为虚构。

### 工具与文件边界

- 工具只访问配置范围内的资料目录；上传文件名和路径不能用于越界读写。
- JD 和文档中的指令均为不可信内容，不能修改系统权限。
- 模型不得执行任意终端命令或任意 SQL；首版没有真实投递和对外发送工具。
- Web 服务默认只绑定本机地址，不直接暴露公网。

### 异常与预算

- 请求超时、重试、工具调用次数、模型调用次数均可配置并有有限默认值。
- 重试计入任务预算；参数错误、鉴权失败等不得无限重试。
- 超预算保存进度、说明停止原因，不继续调用。
- 记录模型请求数、工具调用数、耗时及接口返回的 Token 用量。
- 缺少用量时记为未知，不能记零；按配置价格计算的金额标为估算。

## 6. 验收矩阵

**以下全部是待验证条件，当前 A01–A15 均未验收。** “首次环境检查通过”不等于应用功能通过。

| 编号 | 场景 | 通过条件 | 主要验证方式 |
| --- | --- | --- | --- |
| A01 | 文字型 PDF | 查看原文、提取结果与来源；未经确认不入正式事实 | 合成 PDF 自动测试＋真实文件人工核对 |
| A02 | 不支持的文件 | 明确报错、提供文本替代，不虚报成功 | 扫描/损坏/非法类型样本＋界面检查 |
| A03 | 资料缺失 | 不猜日期、城市、经历和数字；标未知或追问 | 缺字段模拟响应＋人工核验 |
| A04 | 真实 JD | 保留原文，字段可核对，未提供信息不补造 | 存储测试＋真实 JD 核验 |
| A05 | 岗位分析 | 结论有要求与证据，区分明确不符和不足 | 三类分支测试＋逐条人工核对 |
| A06 | 材料草稿 | 人工核验样本无无据新增经历和效果数字 | 来源约束测试＋真实样本人工核验 |
| A07 | 保存与版本 | 原始简历不变、草稿版本可追溯、事实不被污染 | 文件哈希、版本与事实表检查 |
| A08 | 求职状态 | 保存草稿不标已投递；状态有用户操作与历史 | 状态转换与历史一致性测试 |
| A09 | 重启恢复 | 继续等待补充或确认的任务，不重做全流程 | 关闭进程后用同一数据重启测试 |
| A10 | 重复操作 | 重复确认或保存不重复生成业务记录 | 重复请求、并发点击、节点重放测试 |
| A11 | API 故障 | 超时、限流、鉴权失败、非法输出均有限处理并可见 | 模拟模型与 HTTP 故障注入 |
| A12 | 恶意输入 | JD 伪指令不能越权读写、泄漏 Key 或修改规则 | 注入、路径越界、非法工具与参数测试 |
| A13 | 调用上限 | 达上限停止，显示原因和已有进度 | 小预算、重试计费与重启计数测试 |
| A14 | 本地隐私 | Key 不进前端或日志；敏感文件默认不进 Git | 假密钥捕获、输出检查、忽略规则测试 |
| A15 | 可复现运行 | 独立环境按说明安装、配置、启动和测试 | 干净虚拟环境实测与记录 |

### 测试分层

自动化测试默认不消耗真实 API 费用：覆盖校验、状态、版本等单元测试，以及模拟模型驱动的追问、确认、恢复和故障分支。模型模拟与真实调用应显式区分。

真实 API 验证使用少量真实 JD 和用户已确认资料，首批可约 10 个 JD，不要求先制作大型数据集。保留一部分样本用于最终验收，不能反复用留出样本修改提示词。参考答案来自原始材料和人工核验，不仅依靠模型评分。记录样本数、错误类型、修改次数、Token 和耗时。

真实接口未验证时，只有在模拟测试确实通过后才能标记“模拟测试通过、真实接口待验证”。测试集无某类错误不代表系统在任意情况下都不会出错。

## 7. 阶段与最终交付

| 阶段 | 核心交付 |
| --- | --- |
| 一：需求与工程基础 | 需求、计划、环境配置、项目骨架、基础测试、非敏感文本 API 连通性验证 |
| 二：数据与基础界面 | 资料确认、JD 导入、岗位管理和本地存储，验证保存/查询/修改 |
| 三：Agent 最小闭环 | 检索、分析、缺口追问、草稿生成、人工确认保存 |
| 四：可靠性 | 中断恢复、版本、防重复、隐私、预算和故障测试 |
| 五：验收与展示 | 真实样本评测、运行说明、演示材料、局限说明 |

最终至少交付可运行本地 Web 应用、清楚的代码和依赖配置、需求/架构/启动说明、自动化测试和真实样本评测记录、无隐私演示资料、已知限制/失败案例/后续计划。

## 8. 学习验收

每阶段解释解决的问题、设计原因、模型与程序边界、关键代码位置和串联方式、验证方法与限制。允许先小后大，但真实性、密钥保护与危险操作边界不能推迟。

首版完成后，用户应能独立讲清：一次任务如何从输入到保存；LangGraph 状态与业务数据库的区别；检索如何提供证据；工具调用怎样校验执行；中断、重试与重复写入怎样处理；效果、耗时与成本怎样测量。

## 9. 首次工作限制

先检查工作目录、已有文件和开发约定，不覆盖内容；整理需求，区分阻塞问题与可默认事项，检查 Python/Git，给出阶段计划。**首次仅完成需求落盘、环境检查与计划，不一次性生成系统，不创建真实投递任务，不要求聊天中提供 Key。**
