# 个人求职管家 Agent

为一个本地用户服务的求职资料与进展管理应用，同时用于学习 Agent 工程。技术路线为 Python、LangGraph、DeepSeek API、SQLite、FastAPI 与服务端模板。

## 在本机运行

在项目目录打开 PowerShell，已有 `.venv` 时直接运行：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m job_search_agent.cli serve
```

打开 [本地工作台](http://127.0.0.1:8000)。默认只监听本机，浏览首页不调用模型。按 `Ctrl+C` 停止自己在终端启动的服务；端口已占用时先检查是否已有本项目服务。

```powershell
.\.venv\Scripts\python.exe -X utf8 -m pytest
```

完整安装、恢复演示和 API 配置步骤见[运行说明](docs/running.md)；理解代码串联见[阶段一讲解](docs/stage-one-walkthrough.md)。

## 项目边界

业务闭环：确认个人资料 → 导入 JD → 分析证据与缺口 → 按需追问 → 生成草稿 → 用户确认保存 → 手动记录求职进展。

个人资料、数据库和生成材料统一存入本地 `data/`。DeepSeek 请求中的必要文本会发送给模型服务商；第二版简历与 JD 解析会把所选文件的页面图像或文字发送到 DeepSeek；姓名、联系方式等原件内容可能随同发送，页面在操作前明确说明。API Key 仅从本地环境变量或不进入 Git 的配置读取，请勿发到聊天中。

旁边的 `OpenJobAutofill-main` 是已有浏览器填表扩展，本次未修改或接入。新项目不提供自动投递、邮件发送、招聘网站登录或定时任务。

第二版按资料入口、岗位准备、定制简历、联调验收分批推进。现在可在“添加岗位”上传 1–6 张截图或粘贴 JD，用 LLM 解析后核对保存；设为准备中时选择是否分析。只改状态不请求模型，分析完成后自动展示结果。三项工具分别检索摘要、完整经历、原始依据，同一任务相同查询复用结果。新限额为单次输出 102,400 Token、文本请求 100,000 字符、每任务模型 40 次及工具 60 次；已有任务的预算保持不变。第三批现已接入岗位项目推荐、人工选用排序、LLM 完整简历撰写、草稿编辑、版本确认和 Word/PDF 导出，见[第三批交付记录](docs/v2-batch-three-report.md)。模拟面试仍为后续扩展。
